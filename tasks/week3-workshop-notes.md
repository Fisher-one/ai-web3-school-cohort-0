## Session 1：Product Manager of Cobo Agentic Wallet（5/26）

**主讲：** Cobo 产品团队

### Cobo 解决什么问题

传统方案里，Agent 要执行链上操作只有两个选择：
1. 持有 EOA 私钥（全权限，无法约束）
2. 每次要用户签名（失去「自主」性）

Cobo Agentic Wallet（CAW）提供第三条路：**用户设置 Pact（权限策略），Agent 在 Pact 范围内自主签名执行。**

### Pact 机制

- **Pact = 任务级授权**，比 Session Key（账户级）粒度更细
- 支持约束维度：收款地址白名单、单次金额上限、总额上限、有效期、交易次数限制
- Pact 存在链上（或 Cobo 托管层），不能被 Agent 代码篡改

### 适合哪个赛道

Cobo Agentic Wallet 赛道：Agent 持有钱包、自主支付、预算控制。

典型 demo 类型：
- Agent 自主购买链上数据
- Agent 在预算内采购计算资源
- Agent 管理多签钱包的日常操作（在阈值内）

### 我的项目如何对应

| Cobo 能力 | 我的项目使用方式 |
|----------|--------------|
| CAW Pact 白名单 | 限制 Agent 只能付给已知的 Data Worker 地址 |
| 金额上限 | 每次支付不超过 0.002 SETH |
| 链上可审计 | 所有支付记录附在报告页脚，tx hash 可查 |
| Pact 在代码外 | 即使 prompt injection 绕过 Agent 代码，也无法突破 Pact |

### 关键学到的点

**「CAW 的信任边界位置是它与 EOA 的本质差异」**

EOA + Agent 代码的方案：权限约束在代码层 → 攻击者入侵代码 = 突破权限
CAW Pact 方案：权限约束在合约层 → 攻击者入侵代码 ≠ 突破权限

这个论点直接成为我项目的核心安全论述。

## Session 2：从 VC 角度如何更好打磨项目（6/1）

**主讲：** VC 嘉宾

### VC 评估 Hackathon 项目的维度

1. **问题真实性**：解决的是真实存在的问题，还是「工程师眼中的问题」？
2. **市场时机**：为什么是现在？AI × Web3 的 Timing 是否成熟？
3. **技术深度**：demo 背后有没有真正的技术决策？还是只是接了一个 API？
4. **团队执行力**：能不能从 demo 推进到产品？

### 对我项目的启示

**问题真实性**：Agent 自主支付的安全边界是真实问题——现在所有给 Agent 钱的方案（私钥 or 多签）都有缺陷，CAW Pact 是新方法。

**时机**：AI Agent 正在从「聊天工具」转向「自主执行者」，自主支付的安全问题是今天就存在的，不是未来的问题。

**技术深度**：
- 服务发现不是静态字典，是真实 HTTP 探测
- 支付不是 mock，是 Sepolia 链上真实 tx
- Pact 约束不是代码注释，是链上执行的权限策略

**关键教训：**
> 「能运行的最小实现，比一个精美的架构图更有说服力。」

所以 Week 4 的重点是：**Demo 视频 > README > 代码注释**

### 我加进 pitch 里的论点

「我们解决的不是『Agent 能不能付款』，而是『Agent 付款时如何保证边界不被突破』。今天所有给 Agent 钱的方案都有这个问题，我们是其中一个实现了可控边界的早期参考实现。」
