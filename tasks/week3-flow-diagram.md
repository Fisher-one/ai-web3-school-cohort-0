## 关键设计决策

### 为什么用 HTTP 探测而不是静态字典

静态字典：Worker 上线下线需要手动更新配置，不是真正的服务发现。
HTTP 探测：每次 `list_data_workers()` 都向候选地址发 GET /catalog，只返回在线且响应正确的 Worker。这才是「发现」而不是「查配置」。

### 为什么 CAW 比 EOA 更适合这个场景

EOA 方案：Agent 持有私钥 → 可以付给任何地址任何金额 → 一旦被 prompt injection 攻击，攻击者可以清空余额。
CAW Pact：权限约束在链上合约层，不在 Agent 代码里。即使攻击者控制了 LLM 输出，也无法突破 Pact 的白名单和金额限制。

### 为什么 429 比 402 更现实

真实的付费 API（Alchemy、Etherscan Pro）都用限速而不是逐次付款。429 方案：免费额度内正常访问，超出限速后触发升级付款。这比「每次都要先付款」的 402 方案更接近真实商业模式，也更容易做 demo。
