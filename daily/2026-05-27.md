## 学习笔记

### Machine Payment 章节复盘（explain-back）

今天把 Machine Payment 8 个节点用 explain-back 方式过了一遍——不看笔记，凭记忆讲，Agent 查漏补缺。

**讲对的**：Stablecoin Payment（基础稳定币支付）、Budget（预设额度上限）

**方向对但漏了关键点**：
- **Quote**：我以为就是个 struct。漏了——这个是服务方**签过名**的报价，不是 Agent 自己拼的。Agent 拿到后验证签名确认没被篡改，类似后端 JWT 验证。
- **Payment Intent**：我以为就是订单信息。漏了——是用户**签过字的支付承诺**。Quote = 卖家报价，Payment Intent = 买家说好。链上合约看到 Intent 就直接执行，不用再问用户。类似后端查权限不每次查 DB——拿到签过的 JWT 就够了。
- **MPP**：两个机器之间直接谈钱结算，中间没有人类点确认。类似 service-to-service gRPC 调用。

**讲错的**：
- **x402**：完全没搞懂。实际上是一套「自动付钱看内容」的协议。网站返回 HTTP 402 → 带支付要求 → Agent 自动判断 Budget/Policy → 转账 → 拿收据 → 重新请求 → 拿到内容。跟 Agent Wallet 的 Budget + Policy 接上：Budget 管能不能付，Policy 管付给谁。
- **Subscription**：我以为是监控系统。实际就是自动续费——跟 Netflix 月费一样，但不是存信用卡是链上合约定期划钱。
- **Micropayment**：我当订阅讲了。实际是按次极小额支付——0.001 USDC 调一次 API，传统支付系统做不到这么小额。

**核心体会**：读 Machine Payment 的时候我把 8 个节点当独立概念看，没串起来。Agent 帮我理了：Stablecoin → Budget → Quote → Payment Intent 是一条授权链，x402/MPP/Subscription/Micropayment 是四种支付场景的分叉。

### Agent Wallet ↔ Machine Payment 串联

读 Agent Wallet 的时候理解了「Agent 能做什么」，读 Machine Payment 的时候理解了「Agent 能花多少」。两条线接上：

```
Agent 想花钱 → Budget 查额度 → Policy 查规则 → Quote 拿服务方报价
  → Payment Intent 用户签承诺 → Guard 最后拦截检查 → 链上执行 → Receipt 留凭证
```
