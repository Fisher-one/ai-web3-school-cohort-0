### 今日主题：多 Worker 服务发现架构升级

今天把 chain-research-agent 从单体 Agent 升级成了「Agent + 多 Worker 服务发现」架构。之前是 Agent 内部 mock 数据或者硬编码列表——这跟真实的经济系统不搭。今天全部换成真实的 HTTP 探测，Worker 自己注册自己。

### 做了什么

**1. 限速层**

加了一个 rate limit 中间件，不是简单的「超过频率就拒绝」。逻辑是：
- 正常请求 → Agent 直接处理
- 超频率（429）→ 触发 CAW 付款升级通道，用户支付 SETH 获得更高配额

这样限速不是「关上门」，而是「开了一扇收费的门」。这符合 x402 的思路：不是拒绝服务，而是给服务标价。

**2. 结构化报告输出**

LLM 输出的不再是一段自由文本。现在格式是：
- 分析报告（结构化的市场数据解读）
- 支付摘要页脚（用了哪个 Worker、多少钱、tx hash）

这样用户看到的不只是数据，还能验证「我付的钱去哪了」。

**3. 真实服务发现（重点）**

这是今天最大的改动——从静态列表到动态发现。

`agent/registry.py`：
- 不读任何本地字典或配置文件
- 启动时对已知端口做 HTTP 探测（`GET /catalog`）
- 每个 Worker 的 `/catalog` 返回：服务名、价格（SETH）、描述、支持的数据类型
- 探测失败（Worker 没启动）的从列表移除，不影响其他 Worker 正常注册

`agent/tools.py` 新增两个工具：
- `list_data_workers()`：列出当前在线 Worker，包含价格和描述
- `hire_worker(worker_id, query)`：通过 CAW Pact + 链上支付购买数据，返回真实 API 结果

三个真实 Worker，每个调不同的 API：

| Worker | 端口 | API | 价格 | 返回数据 |
|--------|------|-----|------|---------|
| DefiLlama Protocols | 8081 | DefiLlama | 0.001 SETH | 协议 TVL + DEX 24h 交易量 |
| DefiLlama Yields | 8082 | DefiLlama Yields | 0.0015 SETH | 各链 APY/收益率排名 |
| CoinGecko | 8083 | CoinGecko | 0.002 SETH | 代币实时价格 + 市值 |

**完整链路（发现 → 比价 → 采购 → 交付）**：

```
用户提问："比特币现在怎么样"
  → Agent 调 list_data_workers() 发现在线 Worker 列表
  → LLM 自己推理：比特币价格 → 需要 CoinGecko，0.002 SETH
  → Agent 调 hire_worker("coin-gecko", "Bitcoin price")
  → 内部流程：CAW Pact 构造 → 链上支付 → x402 验证 → Worker 返回 CoinGecko 实时数据
  → LLM 生成结构化报告（价格、24h 变化、市值 + 支付页脚）
```

四个环节全部打通，没有 mock 数据。Worker 返回的是真实 API 数据。
