### 项目方案做了什么调整（Agent review 后）

给了 Claude 一份背景文档让它出计划，Agent 看出三个问题：

**1. CAW SDK 排太晚（6/6–6/8 才碰）**
原计划 Go server → CAW → Agent loop，但 CAW 是唯一完全没碰过的黑盒，万一文档缺东西、测试网要审核，三天没缓冲就崩了。调整：现在/明天就做 CAW spike——只发一笔 Sepolia USDC 转账，拿到 tx hash 就算过。通了再排三天不慌，不通直接降级 ethers.js。

**2. Agent loop 不用教 Agent 理解 402**
原计划 Agent 自己处理「请求→402→付款→重发」循环，这个写起来比看起来复杂（retry、timeout、tx 确认等待）。更省的做法：把 x402 交互封在 Agent 的工具函数 `fetch_data` 里，Agent 只看到数据回来，不知道花了钱。Agent loop 变成标准 tool-calling 模式，开发量小一半。

**3. 端到端联调只留了一天（6/11），不够**
三个组件（Go server + CAW + Agent loop）第一次碰一起，八成端口不对、header 拼错、tx 时间超时。调整：Go server 写完当天用 curl 模拟全流程联调一次，后面接入 CAW 只替换「手动付款→SDK 付款」，风险拆成两块。

### Cobo CAW 文档阅读笔记

**文档入口**：https://www.cobo.com/products/agentic-wallet/manual/developer/quickstart-overview

**CAW 的核心设计（四句话）**：
1. 我的运行时拿的是 API key，不是私钥——私钥在 Cobo 那边用 MPC 管着，代码里不碰
2. 钱包 owner（我）在 Cobo App 里配对一次，后续不用重复授权
3. 我的运行时提交一个 pact（授权声明），里面写了能花多少、花给谁、什么时间段
4. CAW 在服务端强制执行这些规则，超限了自动拦截，不用我自己写检查逻辑

翻译成人话：**不用自己管私钥、不用自己写权限引擎，CAW 替你做了。你只负责写"Agent 要干什么"，CAW 负责"这个操作能不能放行"。**

**给我定好的路径（Canonical Path）**：

```
CLI Setup（装 caw + 配对钱包）
  → Python Hello World（跑第一个 pact + 链上操作）
  → Pacts（理解授权对象怎么设）
  → Transfers（发转账）
```

**跑完这条路径后我应该有**：
- 一个配好对的钱包
- 一个被审批过的 pact
- 一笔成功的链上操作
- 一笔被拒的（看拒绝反馈长什么样）
- 一条可查的审计日志

**文档建议我只开三个工具组（别上来就全开）**：

| 工具组 | 包含什么 | 我的项目要哪个 |
|--------|---------|-------------|
| Pact Drafting | submit_pact, get_pact, list_pacts | ✅ 配置授权 |
| Execution | transfer_tokens, contract_call | ✅ 发转账 |
| Observer | list_wallets, get_balance, audit_logs | 🟡 调试点用 |

**有个给 AI 编程助手的彩蛋**——他们文档里写了一句「如果你用 Claude Code / Cursor 开发，跑这个命令让 AI 有上下文」：

**跟我的项目的关系**：

### CAW 文档学到的东西

CAW 的设计思路跟我在 Week 2 画的权限策略基本对上了——它把私钥管理（MPC）、权限检查（Pact）、审批流程都做在服务端，我这边只需要拿 API key 调用 SDK，不用自己写钱包控制层。核心概念就四个：

1. **API key 替代码** — 代码里不碰私钥，Cobo 管 MPC 签名
2. **配对一次** — 钱包 owner 在 Cobo App 里扫码配对，后续不需要重复授权
3. **提交 Pact** — 声明 Agent 的权限边界（金额上限、白名单地址、时间窗口）
4. **服务端执行检查** — 超限自动拦截，返回拒绝原因

文档建议的接入路径：CLI 安装 → Python SDK Hello World → Pact 配置 → 转账。目标跑通：配好钱包 + 审批一个 Pact + 发一笔链上操作 + 处理一次拒绝 + 查审计日志。

### 项目怎么落地的

**技术栈**：Python Agent + Go x402 server + Cobo CAW SDK + Sepolia 测试网

**Demo 流程**：「查 Uniswap 交易量」→ Agent 调 x402 → 收到 402 → CAW 检查 Pact → Sepolia 转账 → 数据回来 → Agent 生成报告 → etherscan tx hash

**时间线 10 天**：明天先做 CAW spike（只发一笔转账验证能通），然后 Go server、CAW 正式接入、Agent loop、联调、Demo 视频，6/12 提交。
